# October 23, 2026 code audit

Rust & Ruin 0.1.0-beta, Minecraft 1.20.1 Fabric, Java 17. Changes remain local for owner testing; this audit does not commit or publish them.

## Findings and fixes

| Priority | Finding | Evidence and correction |
| --- | --- | --- |
| High, build tooling | Gradle 8.6 falls within five published security advisory ranges. | Upgraded to SHA256-pinned Gradle 8.14.6 and its verified wrapper. Loom 1.6.12 is incompatible with this Gradle API, so upgraded Loom to 1.10.5 after an isolated Java 17 compatibility trial. Full compilation and runtime tests follow below. These are build-host/dependency-resolution risks, not Minecraft-player remote code execution. |
| Medium, map permissions | Variant spawn eggs bypassed Adventure `CanPlaceOn` restrictions through the normal item-use path. | A real server-player Adventure fixture failed for the custom egg while the vanilla egg correctly refused. Added native placement permission checks. Positive tests retain explicitly permitted Adventure placement and Survival water use. |
| Medium, gameplay | Rabies subtracted health before mutation multipliers, violating both the one-heart rate and the two-heart floor. | A 30-HP tetanized zombie lost 3 HP instead of 2 per minute and eventually reached a 1-HP cap. Normalize the modifier after vanilla health operations, reconcile changing bonuses, preserve the floor, migrate the older additive penalty, and avoid replacing unchanged modifiers every tick. Tests also cover save/load, cure, naturally low health, and the native attribute cap. |
| Medium, spawning | Air use of a variant egg accepted solid-block raycasts and spawned creatures inside blocks. | Reproduced through `ServerPlayerInteractionManager.interactItem`. Restrict air use to fluid blocks, matching native spawn eggs. Reject empty/wrong stacks at the spawn helper. Ordinary block placement remains supported. |
| Low, inventory | Beacon shift-click rejected every non-netherite item, including main-inventory/hotbar transfers. | Reproduced with Dirt. Route normal inventory transfers and consult the actual netherite-only payment slot; the superclass retains an obsolete private slot reference. Tests verify two-way transfers, invalid payment rejection, one-ingot transfer from a stack, and payment retrieval. |
| Low, attribution | Rusty nails hitting Endermen used unowned magic damage and lost the thrower's combat credit. | The hit reduced health but left the attacker's identity unset. Use an owner-bearing magic damage source while preserving the Enderman projectile-immunity workaround. |
| Low, disease state | Clearing Rabies before the first minute left its partial timer behind. | Removing the effect with 1,199 ticks elapsed retained that timer. Clear early counters when Rabies is absent, so a later infection starts a new interval. Normal Rabies Cure still resets all state. |
| Low, performance/save behavior | Unchanged dry caltrops and bear traps marked chunks dirty every second. | Direct block-entity ticks changed a clean chunk's save flag without any persisted state change. Save only changed weather progress; save interrupted exposure resets immediately. Native rust conversion and captured-victim persistence tests remain passing. |
| Low, JEI layout | Rusting instructions extended outside their recipe area; coating text lacked wrapping for longer values. | Inspected the existing screenshot and source, then wrapped the affected labels and enlarged their backgrounds. Fresh JEI screenshots show complete rusting, coating, and smithing instructions. |

A final warning-enabled build also identified execution-time access to `Task.project` during metadata expansion, deprecated for removal in Gradle 10. Capture the version during configuration instead. This preserves the expanded metadata while removing that future build failure.

The initial eight new regression tests all failed before their corresponding gameplay fixes. The original 192 tests passed in that same run. The corrected suite first passed 200 tests, then 205 after five additional boundary/persistence tests. The final repeat and client results are recorded in the evidence below.

## Security advisory scope

These official Gradle advisories apply to the previous 8.6 build wrapper and are patched by 8.14.6:

- [GHSA-xwqc-3h47-hg64](https://github.com/gradle/gradle/security/advisories/GHSA-xwqc-3h47-hg64): unauthenticated client-to-daemon Java deserialization. Requires access to the same build host; it is not remotely exploitable over the network.
- [GHSA-mvvg-497x-hmj8](https://github.com/gradle/gradle/security/advisories/GHSA-mvvg-497x-hmj8): unauthenticated worker-to-daemon Java deserialization. Requires a local attacker to win the worker connection race.
- [GHSA-j5m7-59rp-24f5](https://github.com/gradle/gradle/security/advisories/GHSA-j5m7-59rp-24f5): repository fallback after SSL connection failures can expose builds to malicious artifacts under the advisory's repository-control conditions.
- [GHSA-w78c-w6vf-rw82](https://github.com/gradle/gradle/security/advisories/GHSA-w78c-w6vf-rw82), CVE-2026-22816: unsafe fallback after unknown-host failures.
- [GHSA-mqwm-5m85-gmcv](https://github.com/gradle/gradle/security/advisories/GHSA-mqwm-5m85-gmcv), CVE-2026-22865: unsafe fallback after repeated transient repository failures.

The February 2025 temporary-directory advisory affects Gradle 8.12 on Unix; it was not an applicable finding for Windows with 8.6. Older advisories on the current Gradle security list predate the project's former wrapper. No Gradle deserialization exploit payloads were executed.

Official distribution and wrapper SHA256 values were retrieved over HTTPS and checked before adoption. The wrapper generated from the verified distribution matches the published wrapper checksum. The existing quoted Windows launcher is retained because the project path includes an ampersand.

## Remaining risks and test limits

- Other inventory mods can also claim native slot 46, which this mod uses for gloves. Compatibility with arbitrary inventory-overhaul mods is unverified; an accessory-slot integration would be preferable for larger modpacks.
- Configuration is administrator-owned local JSON, read as a whole and rewritten at startup. Atomic replacement, a size limit, and preserving malformed input for diagnosis would improve failure recovery. This is not a demonstrated remotely supplied input vulnerability.
- Generated mob skins rely on resource-pack textures. Exceptional failures between decoding and texture registration could leak an image allocation, and modded entities with many dynamic texture identifiers may grow the cache until reload. Normal vanilla textures and reload cleanup were reviewed; unusual resource packs/modded renderers need testing.
- A third-party mod that rejects an effect during refresh may interact poorly with replacement of existing infection effects. No failing vanilla reproduction was found, so this remains an interoperability hypothesis.
- Dependency checksum verification and stricter per-repository content filters would add supply-chain protection beyond the pinned Gradle distribution/wrapper. This audit did not establish an exhaustive, transitive vulnerability inventory for Minecraft and every optional viewer library.
- Runtime tests exercise a dedicated Fabric GameTest server and integrated clients with the declared versions. They do not prove compatibility with every modpack, permissions plugin, resource pack, network latency condition, or long-running public server. Release packaging is inspected separately; production hosting and multi-client owner playtesting remain useful.
- The code remains heavily compressed in several classes and generators build on older staged definitions. This makes future changes harder to review, even where current output is correct. A focused readability/resource-generator consolidation would reduce maintenance risk.

No code audit can establish that a mod is 100% bug-free. The confirmed findings above are fixed and tested; the items in this section are bounded follow-up risks, not claims of newly reproduced exploits.
